## AI Agent工程师

### 职位要求

1、2027届获得本科及以上学历，计算机、软件工程等相关专业优先；
2、开发语言和技术栈不限，熟悉Golang/Python/TypeScript优先，并熟悉常见的软件开发模式；
3、对AI应用方向有强烈的兴趣，熟悉Agent相关的常见范式架构，如Plan&Execute、ReAct、Workflow等，熟悉模型的工作原理和特性，并能结合原理和特性做稳定性、成本和效果优化优先；
4、业务理解能力强，能够针对业务上的需求梳理业务边界并快速匹配最适合的Agent工作流式；
5、对行业流行的常见模型优缺点有大致的了解，并了解如何系统科学的评测帮助做模型选型；
6、掌握模型原理优先，对常见的CNN、RNN、Transformer模型结构及推理架构有一定的了解优先，对模型的二次训练原理及方法了解优先，如SFT、LoRA-SFT、DPO等。

HR批注：简历里最好写一个完整 Agent 项目：任务目标是什么、接了哪些工具、如何处理失败、最终效果如何评估。

HR批注：如果做过 RAG、自动化工作流、智能客服、代码助手、数据分析助手等项目，可以重点准备链路设计和效果评估。

HR批注：面试中不要只讲框架名。更重要的是讲清楚你为什么这样拆任务，为什么需要这个工具，以及异常情况怎么处理。

# 面试官在线"透题"

**Q1.** 现在很多信息抽取任务可以用 LLM 完成，你会如何判断该用专用小模型，还是直接调用 LLM？两者怎么结合更划算？

这道题考察候选人对信息抽取任务技术选型的判断能力。这道题希望同学能从成本、延迟、数据量、schema 稳定性等维度综合判断，而不是简单认为专用小模型或 LLM 一定更优。如果能进一步想到一些组合方案，比如用 LLM 蒸馏小模型，或采用"小模型 + LLM 复核"等方式，那就更好啦！

**Q2.** 你的论文做了 AI 生成文本检测，也提到方法在水印扰动、跨模型、跨领域下容易失效。如果要把这套论文方法做成线上检测服务，工程落地会遇到什么问题？遇到没见过的新模型时，你会怎么处理？

这道题考察候选人是否能理解学术 benchmark 和真实开放世界之间的差距。学术数据集往往分布更干净，但线上场景会遇到跨模型、跨领域、水印扰动和未知新模型等问题。因此，回答时建议不要只关注论文中的 SOTA 指标。如果能进一步结合线上落地场景，提出一些能真实落地组合方案，比如"持续更新 + 概率化输出 + 人工兜底"会更好。

**Q3.** 作为 Agent 工程师，如果用户根据不同细分场景定义了几百个 Skill，导致 Skill 召回准确率下降，你会怎么解决？

这道题考察候选人是否真的思考过如何落地 Agent 项目，并理解真实用户使用中会遇到的问题。随着 Skill 数量增加，召回准确率下降是实际落地中常见的问题。如果同学能从架构优化和召回质量两个方向作答，例如分层召回、上下文感知、召回路由、召回策略优化和 query 优化等，回答会更完整～

走进岗位真实的一天

对 AI Agent 开发工程师来说，日常工作不是简单"用 AI 写代码"，而是让 Agent 真正能在业务场景里完成任务：理解用户意图、调用合适工具、处理异常结果，并持续验证效果是否稳定。

上午　对齐场景，拆解 Agent 的任务链路

先明确今天要解决的业务问题：Agent 要帮用户完成什么任务，什么时候需要调用工具，什么时候需要追问用户，哪些结果算成功。
同时会拆清楚工具接口、知识库、长短期记忆、权限边界和验收标准，避免只做一个"看起来能跑"的 Demo

下午　开发能力，分析 Trace，做评测调优

进入实现阶段后，会用 AI Coding 工具辅助开发 Agent 工作流、工具调用、参数校验、重试降级、上下文管理等模块。
更关键的是反复看 Trace：模型为什么选错工具、参数为什么填错、哪里出现幻觉、失败后该怎么兜底，再通过评测数据不断调整。

下班前　Review 代码、验证效果和安全边界

一天结束前，会检查 Agent 是否真的完成任务，而不是只返回一段"像样的回答"。需要 Review AI 生成的代码，补充测试和 badcase，确认工具调用、权限控制、异常处理都可靠。AI 提高了开发速度，但最终质量仍然由工程师负责。

*"一天的工作"仅作参考，主要帮助大家了解 AI 全栈工程师可能参与的典型工作流程。实际工作中，不代表每天都需要完成这些环节，也不代表所有任务都会在一天内发生。

岗位求职Tips

Tips 1

如果有对应Agent 项目经历，一定要完整呈现

简历中，项目描述一定要清晰。在面试前可以提前复盘，讲清楚项目中 Agent runtime 怎么跑、工具怎么定义和调用、参数怎么校验、记忆怎么设计、失败 case 怎么处理……

Tips 2

介绍项目注意提前回顾技术细节

在字节跳动，技术基础一直是核心考察项。面试官会通过追问项目背景、技术选型、具体实现和踩坑过程来考察候选人技术思考的深度。比如 Function Calling 场景里，工具选错怎么办，参数非法怎么办，调用失败怎么重试或降级，如何评估 Agent 是否真的可用等。

Tips 3

展示主动探索，而不是包装经历

目前这个方向成熟人才少，面试时主动展现自己的主动探索能力很重要。即使没有相关项目经历，也可以呈现自己研究过的Agent 工具、MCP、Skill、记忆、知识库、安全防线等内容。
