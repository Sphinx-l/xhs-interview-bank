阿里淘天 AI Agent 全栈开发｜一面面经（2026 秋招 真实现场版）
岗位：AI Agent 应用研发（全栈，后端+Agent 编排+RAG 工程）
面试时长：约 60min
面试背景：校招，业务侧研发面试官，偏工程落地，淘天电商 Agent 方向；不开摄像头，喜欢顺着回答持续追问，很多场景题无标准答案，重点看取舍、兜底方案。
面后情况：面完 3 天收到二面通知。

> 来自 02.webp（一、开场 5min）

1. 自我介绍，重点讲和 Agent 相关项目，不要堆实习流水账。（发帖人注：我当时直接挑了电商知识库 RAG+工具调用导购 Agent 来讲，说了自己负责模块、线上指标、遇到的 badcase。）
2. 面试官：你这个项目是 demo 还是跑过小流量？核心解决业务什么痛点？（发帖人注：这里很容易被深挖，千万别说点是自己本地玩的 demo，淘天一面很看重能不能落地。）

> 来自 03.webp（二、项目连环拷打 25min，一面重头戏）

3. 你这个导购 Agent 链路是什么？每一层你做了哪些优化？
4. 你用了 LangGraph，讲下你节点怎么划分？State 里面存什么？什么时候做持久化？
5. 为什么选 LangGraph 而不是自己写编排？有没有遇到过循环死跑、空转的情况？怎么限制最大迭代轮次？
6. 项目里 RAG 是怎么做的？电商商品文本、规格、活动文案混杂，chunk 策略怎么设计？纯固定窗口切分有什么问题？
7. 召回之后做了重排吗？用的什么方案？线上怎么判断召回是好还是坏？你有哪些评估指标？

> 来自 04.webp（项目连环拷打续）

8. 幻觉问题你怎么控？除了 prompt 约束，工程层面做了哪些校验？召回文档和输出结果的引用溯源怎么做？
9. 工具调用：Function Calling 经常参数错、格式乱，你怎么处理重试和校验？有没有做工具的权限隔离、沙箱？（会问到 MCP、Skill 概念，区分三者）
10. 追问：同一个会话多轮调用多个工具，工具之间数据冲突怎么办？
11. 记忆分层你怎么设计？短期、会话、长期记忆分别存在哪里？Redis、向量库分别什么时候用？会话上下文太长 token 超限怎么压缩、摘要、遗忘？
12. 有没有做链路观测？Trace 埋哪些关键节点？线上 badcase 怎么回流迭代？

> 来自 05.webp（三、Agent & LLM 基础技术题 15min）

13. ReAct 和 Plan-and-Execute 两种模式区别，你项目里怎么选？各自优缺点，什么时候混合使用？
14. CoT 是不是一定能提升效果？有什么负面问题？token 成本、延迟怎么权衡？
15. KV Cache 是什么，为什么能加速推理？
16. Temperature、TopP 参数在 Agent 工具调用场景一般怎么调？为什么工具调用不能开太高 temperature？
17. 讲下 RAG 常见的失败 case：检索到相关文档但是回答错、召回无关文档、query 歧义，分别怎么优化？（query 改写、扩展、历史上下文改写）
18. 简单区分 Workflow 和 Agent，面试官喜欢问：带工具调用的固定流程算不算 Agent？

> 来自 06.webp（四、后端工程&计算机基础 10min，全栈岗必问）

19. 手撕算法：合并区间（现场白板写，要求考虑边界，空数组、重叠、包含；不是难题，但是要看编码习惯、边界处理，写完会追问时间复杂度）
20. 限流怎么实现？令牌桶、漏桶区别，电商高并发导购 Agent 接口适合哪一种？
21. Redis 大 key 问题，你怎么排查、拆分？会话记录存在 Redis，量大之后有什么隐患？
22. MySQL 索引，联合索引最左匹配，简单场景题。

> 来自 07.webp（五、场景开放题 5min + 反问）

23. 如果上线之后，Agent 调用工具成功率暴跌，你排查思路是什么？从哪几层开始定位（模型侧/编排侧/工具服务侧/权限侧）？
24. 电商场景，用户问价格、优惠券，工具接口偶尔超时，怎么设计降级和兜底？能不能直接让大模型瞎猜？

反问环节（发帖人问：这个团队目前 Agent 主要落地在哪些电商场景？是导购、售后还是商家侧工具 Agent？）：面试官答目前在做商家智能助手、商品问答 Agent，在推 MCP 标准化工具接入，现在大量在做 Harness 评测体系建设，不是只做 demo。

> 来自 08.webp（末图：面试复盘/备考提醒）

1. 千万不要只会背概念，面试官一听到你背定义，马上切场景追问，淘天这边很看重电商业务场景，所有 RAG、工具调用、记忆都要往业务上靠；
2. MCP、Skill、Harness 是今年阿里 Agent 岗高频新词，一定要搞懂，很多人栽在这里，只会 LangGraph 但是不知道 Harness 评测体系；
3. 一面难度中等偏扎实，算法不是 hard 难度，但是工程问题连环追问，很看重你有没有真实踩坑，有没有线上排查经验；
4. 不怎么深挖 Transformer 底层数学，但是会问推理优化、token 成本控制，毕竟业务要控成本；
5. 坑点提醒：不要吹自己什么都做过，只要某一块说不清楚细节，面试官会持续压着问，很容易露馅。
