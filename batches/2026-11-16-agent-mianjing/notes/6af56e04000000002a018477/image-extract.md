1. Harness 和 RL 是什么关系？遇到问题先改哪个？

自答要点：先分两种 harness——推理时 harness（工具、提示、上下文管理、记忆；人或 LLM 编辑器改）与训练时 harness（出题分布、生成提示、评分标准；训练中动态改）。判断顺序：先 harness 后 RL——失败先归因：格式错、工具描述不清、上下文爆了→改 harness（便宜、立刻生效）；长程决策差、不会纠错、探索不够→才上 RL 把行为内化进权重。
追问：训练和部署用的 harness 不一样会怎样？→ 模型学到的是训练 harness 下的行为，模板、截断、工具返回格式一变就掉点；训练要尽量用线上同一套 harness（例：阿里 QwenGyre 直接在不改动的 Claude Code 里做 RL）。

2. Agent RL 前为什么一定要 SFT？什么时候开始上 RL？

自答要点：RL 只能强化「偶尔会做」的行为——工具调用格式都写不对则组内优势全 0 学不到；SFT 负责格式、工具用法、什么时候停，RL 负责长程决策、试错纠错。时机看 SFT 后成功率：<5% 补 SFT 数据或换简单题；10%~70% 最适合上 RL；>90% 换难题。追问 SFT 训多了副作用：熵被压得太低，RL 阶段探索不出新行为。（参考：腾讯 T1 在 122B MoE 上 SFT 49.4→RL 64.0）

3. 采样上有什么技巧？

自答要点：①按难度筛题（每题先跑 8 次只留成功率在 0 和 1 之间的）；②动态补采（DAPO 丢全对/全错组重采；HarnessRL 给已会题降采样权重）；③长尾别等（发 560 条收先完成的 512 条，最难最长任务需单独补）；④训推对齐（拼序列用推理端原始 token id；MoE 回放生成时选的专家）；⑤截断轨迹单独处理（判 0 会惩罚「做得慢但在做对」，可只 mask 不训练）。

4. 怎么防 reward hacking？

自答要点：设计奖励时能用可验证结果就不用打分模型；格式分给小或不给；部分分用差值不用状态分（防拖长轨迹）。改评分标准时：同一组回答用新标准重打分，平均分必须下降才采纳。训练中盯三个信号：奖励涨但真实成功率不涨（钻空子）、轮数长度一路涨（刷步数）、熵骤降（收敛固定套路）。每隔几步人工抽看高分轨迹；防测试代码泄露给 Agent。

5. 整个 RL 过程里，印象最深的坑？

自答要点：坑一：比值一开始就不对（训推两套引擎同样权重算出的概率有差、token 重新编码、MoE 专家选得不一样；拼序列用原始 token、回放专家压误差）。坑二：最好的 checkpoint 把东西忘了（RL 后期最高分模型做不对早期会的题，历史并集比它多一大截；保留中间 checkpoint，先试合并，不够再当老师做在线蒸馏）。追问怎么发现：按题看每个 checkpoint 做对哪些题，算并集差。

> 来自 07.webp（三面 · 数据与上线，题 6）【训练向，不编题】

6. SFT 数据质量怎么提？

自答要点：来源三路（强模型蒸馏/自己模型拒绝采样/线上 bad case 人工修）；用 RL 同一套判分过滤；轨迹去冗余（删重复调用、无效工具步）；保留「失败后恢复」样本（最稀缺最值钱）；去重和配比（语义聚类去重、难度分层、混通用数据防遗忘）；格式一致。追问怎么证明数据变好了：小规模训几版做数据消融，看下游成功率而不是 loss。

> 来自 08.webp（三面 · 数据与上线，题 7）【应用向，可编题】

7. 最终怎么提升线上准确率？

自答要点：第一步：离线评测先和线上对齐（评测集从线上真实分布采样、按场景切片；离线涨线上不涨多半是评测集不像线上）。第二步：bad case 归因分层修——意图没识别对→改路由/分类；工具或检索出错→改 harness、工具描述；知识或能力不够→补 SFT 数据；长程决策差→上 RL。第三步：灰度上线盯过程指标（任务成功率之外看工具调用失败率、平均轮数、延迟；简单问题让小模型直接答，复杂的才走 Agent，准确率和成本一起优化）。

> 来自 09.webp（三面 · 系统设计，题 8 上半）【应用向，可编题】

8. 调研、执行多个垂域专家，框架怎么设计？

自答要点（Harness 侧）：路由层（意图分类判断走哪个专家）；主 Agent 编排（拆任务、分派、汇总）；调研专家（检索、阅读、引用核验）与执行专家（工具、代码、沙箱）；共享层（记忆、工具注册与权限、统一轨迹日志）。子 Agent 上下文隔离，只把结论回传主 Agent；记忆分层，常用的少量注入，其余按需检索；轨迹日志统一格式，直接给训练用。

> 来自 10.webp（三面 · 系统设计，题 8 追问）【训练向为主，不编题】

追问：训练侧怎么做？一个模型还是多个？

自答要点：三方案对比——一个模型混合多域 RL（部署简单但域间跷跷板）；每域一个专家 LoRA+路由（互不干扰但部署维护成本高、路由错一步全错）；分域训专家再多老师蒸馏回一个（兼顾，部署一个模型）。选择第三种：各域先单独 RL（调研域用评分标准加引用核验，执行域用可执行验证），再在线蒸馏合到一个学生，每道题只跟「在这道题上更强」的老师学。追问混合训练防跷跷板：按域控制采样比例，每个域单独看验证集。
