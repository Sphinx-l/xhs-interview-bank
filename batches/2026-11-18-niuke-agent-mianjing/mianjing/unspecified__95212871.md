- 27届 AI Agent 面经：被上下文压缩和记忆机制问穿了
- 全程约 28 分钟，主要围绕实习项目里的 Agent 记忆模块追问，中间还要求共享屏幕，现场调研成熟产品的实现。
- 一、开场与项目背景
- 自我介绍，讲一下实习和项目经历。
- 平时对什么感兴趣？怎么学习和了解 AI 新技术？
- 有没有 DevOps、云服务器部署和全栈开发经验？项目是否上线？
- 过程中还问了高考数学成绩，要求关闭简历、共享屏幕，再口头介绍项目。
- 二、Agent 记忆模块深挖
- 我从实习中的记忆模块讲起，介绍了用户隔离、用户档案、上下文压缩，以及后续接入 PostgreSQL 和 pgvector 的思路。
- 随后开始连续追问：
- 你说做了上下文压缩，具体怎么压缩？
- 压缩过程和 MySQL 存储分别是什么关系？
- 为什么从 MySQL 换成 PostgreSQL？
- 向量怎么生成，怎么检索？pgvector 在里面负责什么？
- 用户数据具体怎么存？如果有百万级用户，表结构怎么设计？
- 你提出的分库分表方案有依据吗，还是自己的猜想？
- 这部分我的回答比较偏概念，具体实现和方案依据讲得不够扎实。
- 三、现场调研
- 面试官让我用大约 5 分钟，现场查一下 DeepSeek 等产品，以及成熟 Agent 的记忆机制，全程共享屏幕。
- 接着继续被追问：
- Claude Code 具体怎么实现？你确定它用了数据库吗？
- 聊天记录中的信息怎么抽取？
- 怎么判断一条信息属于用户偏好、值得保存？
- 什么情况下更新记忆？
- 你说上下文快满了再处理，怎么判断“快满了”？
- 压缩的完整过程是什么？
- 四、最后留下的四个问题
- 模型上下文为什么会爆？触发处理的阈值怎么设计？
- 上下文／记忆具体怎么压缩？重点讲过程。
- 各家 Agent 产品的记忆机制是怎么设计的？
- Agent 一定需要记忆吗？现有记忆架构是否合理？
- 最大的感受是，项目里写了“长期记忆、上下文压缩、向量检索”，就要能继续回答：谁来执行、什么时候执行、输入输出是什么、失败后怎么办，以及为什么需要这个模块。
- 以后介绍项目，得把自己实际实现过的、调研确认过的，以及暂时的设计设想分清楚。尤其介绍其他产品时，需要有官方文档或源码依据。
- 共享屏幕现查那段，考的是你会不会从成熟产品里拆方案。记忆这块说清什么时候压缩、压缩后靠什么召回就够，这类追问链我拿面灵按岗位模拟过。
