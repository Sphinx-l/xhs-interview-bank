# 掘金面经采集与筛选

与 harvest-xhs-interviews 同一套处理方法与产出规格（筛选规则、mianjing/ 格式、统计口径完全一致，直接沿用），差异只在**来源与采集通道**。本 Skill 不编写答案。

## 批次建立

- 批次目录：`batches/YYYY-MM-DD-juejin-<slug>/`，结构同前：`README.md`、`manifest.json`、`screening_log.md`、`mianjing/`（主产物）、`cards_frozen.json`、`details_collected.json`、`_decisions.json`。
- 不与其他来源混批；公司/岗位/轮次同样为发帖人自述、未核实。

## 渠道维度（必录）

- 每篇题源记录 `channel`：`社招` / `校招` / `实习` / `未标注`（按帖内标记推断，推断性质在 reason 注明）。
- **采集优先级：社招 > 校招 > 实习**。定向关键词示例：「社招 Agent 面经」「大模型 社招」「X 年经验 Agent」。

## 掘金来源特点（与小红书/牛客的差异）

- **入口**：掘金搜索 `juejin.cn/search?query=<关键词>`（文章类型为主），或标签页（如 `backend`、`ai` 标签下筛「面经」）。先验证一种入口能稳定翻页/加载，再批量。
- **长文为主**：掘金面经是 Markdown 长文，题面、甚至完整答案都在正文里；题面与答案混排——**只取题面行**（按原帖顺序），答案内容不入 mianjing/（当前阶段不编不收答案）。
- **内容农场浓度高**：掘金大量「N 道面试题」「面试题合集」「高频题清单」类专栏文章是 AI/人工攒的教学合集，**无真实面试来源**——这是掘金主要的排除对象。判定：无具体公司/轮次/日期、题面泛化（「什么是 RAG」式科普题堆叠）、文末引流（公众号/星球/课程）。
- **真实面经特征**：标题带公司+轮次（如「字节 Agent 开发一面」）、正文有个人叙事（项目拷打、凉经、OC 时间线）、题目与候选人项目强相关。
- **链接形态**：文章 URL `juejin.cn/post/<数字ID>`，无需 token；冻结清单仍保存完整 href。
- **登录墙**：多数文章免登录可读；部分专栏需会员/登录，如实记 `fetch_failed`，不猜测补录。沸点（短动态）题面信息少，一般不采。
- **反爬中等**：单次浏览器程序 ≤15 个页面访问，节奏放慢。

## 采集工程注意事项（与 XHS 相同）

- 全程只用一个浏览器标签页（用户机器为弱配置），tabbit 任务 `--tab` 复用；长任务拆小步、结果落盘可断点续跑；程序被硬截止终止后页面会 crash，要 finish 旧任务、新开任务再用新页面。

## 筛选规则

**完全沿用 harvest-xhs-interviews 的规则**，掘金侧重点：

- 范围硬规则：仅 Agent/大模型开发技术方向；不采 AI 产品经理/运营/前端/纯 Java 八股岗。
- 排除：内容农场合集（见上）、营销引流、方法论备考文、沸点短动态。
- AI 生成模板假面经：跨文章题面逐条同文即假。
- 转载重复：同题面多帖合并，保留一篇为题源，其余标 `duplicate_repost` 并写明合并目标。

**掘金特有**：

- **跨源转载判定（重要）**：掘金面经文章常汇总自牛客/小红书/知乎。与既有批次题面列表比对，逐条同文的标 `cross_source_repost`，注明「与 <批次>/<笔记> 同源」；题面只入一次，来源文都留链接作证据。掘金文章若是对多篇真实面经的**汇编且注明来源**，按汇编处理：逐段归到对应公司，无法归属的段不入库。
- 文中自带答案的，只提取问题行；答案留给未来答案阶段参考（在 manifest reason 注明「原文含答案」）。

## mianjing/（主产物）

格式与 XHS/牛客批次完全一致：

- 每篇题源一个文件：`<公司>__<post_id前8位>.md`，头部为来源链接、公司/岗位/轮次（自述未核实）、渠道、题目数；正文按**原帖顺序**逐条列全部题目（含自我介绍、手撕、反问）。
- `mianjing/README.md`：按公司汇总索引（含渠道标注）。
- 待补采的篇目在索引中标注。

## manifest.json 核心字段

同前：`note_id`（掘金文章 ID）、`url`、`title`、`published_at`、`status`（`retained` / `excluded` / `duplicate_repost` / `cross_source_repost` / `fetch_failed`）、`reason`、`company/role/round`（自述）、`channel`（社招/校招/实习/未标注，推断）、`question_ids`。统计口径与前一致，另单列「跨源判重数」。
