# 牛客面经采集与筛选

与 harvest-xhs-interviews 同一套处理方法与产出规格（筛选规则、mianjing/ 格式、统计口径完全一致，直接沿用），差异只在**来源与采集通道**。本 Skill 不编写答案。

## 批次建立

- 批次目录：`batches/YYYY-MM-DD-niuke-<slug>/`，结构同 XHS 批次：`README.md`、`manifest.json`、`screening_log.md`、`notes/<post_id>/`、`mianjing/`（主产物）、`cards_frozen.json`、`details_collected.json`、`href_map.json`。
- 与 XHS 批次不混批；公司/岗位/轮次同样为发帖人自述、未核实。

### 渠道维度（2026-11-18 新增，重点搜集社招）

- 每篇题源必须记录 `channel`：`社招` / `校招` / `实习` / `未标注`（按帖内「社招/秋招/春招/N届/实习/工作N年」等标记推断，推断性质在 reason 注明）。
- **采集优先级：社招 > 校招 > 实习**。定期用定向关键词补社招：「社招 Agent 面经」「大模型 社招」「Agent 社招 一面」「X 年经验 大模型」等；公司/岗位/轮次齐全的社招帖优先复核。
- manifest 与 mianjing/ 索引都要展示渠道。

## 牛客来源特点（与小红书的差异）

- **入口**：牛客搜索（`nowcoder.com` 搜「Agent 面经」「大模型面经」等）或讨论区面经标签/公司专区。先验证一种入口能稳定翻页，再批量。
- **正文为主**：牛客面经绝大多数是**全文正文**，题面直接在帖子里，图片少；评论区偶有楼主补题，需读评论。
- **公司/轮次常在标题**：如「字节跳动 Agent开发 一面」，直接解析；帖子自带公司/岗位标签时一并记录，仍标自述未核实。
- **链接形态**：帖子 URL 一般无需 token，但**搜索结果里的链接才是稳定入口**，冻结清单仍保存完整 href（`href_map.json`）。
- **登录墙**：部分内容需登录，经用户已登录浏览器操作；遇登录墙/风控如实记录并停止，不轮询猜测接口，不持久化 Cookie/令牌。
- **反爬较严**：翻页节奏放慢（比小红书更保守），单次浏览器程序 ≤15 个页面访问，明显变慢即暂停休息。

## 采集工程注意事项（与 XHS 相同）

- 全程只用一个浏览器标签页（用户机器为弱配置），tabbit 任务 `--tab` 复用；长任务拆小步、结果落盘可断点续跑；程序被硬截止终止后页面会 crash，要 finish 旧任务、新开任务再用新页面。

## 筛选规则

**完全沿用 harvest-xhs-interviews 的规则**（此处只列要点，细则以该 Skill 为准）：

- 范围硬规则：仅 Agent/大模型开发技术方向；不采 AI 产品经理/运营/前端/纯 Java 八股岗。
- 排除模式：营销卖课/AI 生成合集、方法论备考杂谈、剧情日常。
- AI 生成模板假面经：跨帖题面逐条同文即假。
- 转载重复：同题面多帖合并，保留一篇为题源，其余标 `duplicate_repost` 并写明合并目标。

**牛客特有**：

- **跨源转载判定（重要）**：小红书面经大量转载自牛客。新批次整理时与既有批次（XHS 与牛客）的题面列表比对，逐条同文的跨源帖在 manifest 标 `cross_source_repost`，mianjing 索引里注明「与 <批次>/<笔记> 同源」；题面只入一次，来源帖都留链接作证据。
- 楼主在评论区补题的，补进题面并在 screening_log 记录「评论区补题」。

## mianjing/（主产物）

格式与 XHS 批次完全一致：

- 每篇题源一个文件：`<公司>__<post_id前8位>.md`，头部为来源链接、公司/岗位/轮次（自述未核实）、题目数；正文按**原帖顺序**逐条列全部题目（含自我介绍、手撕、反问）。
- `mianjing/README.md`：按公司汇总索引。
- 待补采的篇目在索引中标注。

## manifest.json 核心字段

同 XHS：`note_id`（牛客帖子 ID）、`url`、`title`、`published_at`、`status`（`retained` / `excluded` / `duplicate_repost` / `cross_source_repost` / `fetch_failed`）、`reason`、`company/role/round`（自述）、`channel`（社招/校招/实习/未标注，推断）、`question_ids`。统计口径与 XHS 一致，另单列「跨源判重数」。
