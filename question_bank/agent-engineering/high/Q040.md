# Q040 · Coding Agent 从用户提出需求到编码、测试的完整流程怎么设计？需求澄清、Spec/技术设计/任务拆解怎么区分？各阶段产物如何客观比较与确认？

Agent 工程化与运行环境 · 高 · `Coding Agent` `需求澄清` `Spec设计` `产物评审`

> 真题来源：虾皮 · Agent 开发 · 一面/二面 · 同题另见 7 处（发帖人自述，未核实）

## 背景描述

Coding Agent 是 Agent 落地最深的场景，这道系统性设计题覆盖需求→设计→拆解→实现→验收全链，追问密度极高。

## 引出的痛点

跳过需求澄清直接生成 Todo 开写，是最常见的失败模式——模糊需求下的代码再漂亮也是错；各阶段产物（PRD/TD）没有客观比较手段，迭代就靠感觉。

## 考点

阶段划分与各阶段产物定义、澄清的策略、PRD/TD Agent 的设计、产物的确认与客观比较、防止幻觉。

## 思考方向与解题思路

按『澄清→Spec→技术设计→拆解→实现→验收』逐段设计，每段给输入输出与质量控制。

## 推荐答案

流水线五段：需求澄清 Agent 补全模糊需求（覆盖度检查的提问清单）→ Spec Agent 产出结构化需求规格 → TD Agent 产出技术设计（选型、接口、风险）→ 拆解为带验收标准的任务清单 → 实现 Agent 逐任务编码跑测试；各阶段产物用固定 rubric 评审 + 用户显式确认门禁推进，产物比较用评分维度而非整体印象。

- 澄清段：识别缺失信息（边界、异常、非功能需求），生成覆盖完整性的提问清单分批问用户；问得准比问得多重要。
- Spec 段：输出结构化需求（目标、范围、用户故事、边界、验收标准），回答『做什么』；未确认不进入设计。
- TD 段：回答『怎么做』——选型与理由、模块接口、数据结构、风险与权衡；新系统、改造、重构用不同模板。
- 拆解段：任务粒度以可独立验收为准，每任务带验收断言（测试即规格）；不允许无验收标准的任务。
- 实现段：逐任务编码+测试+自检，验收断言全绿才进入下一任务；失败回流到拆解或设计层归因。
- 产物比较：PRD/TD 用固定评分维度（完整性/一致性/可测性/风险覆盖）由裁判模型打分 + 人工评审关键项；用户确认走结构化 diff（改了哪些条款）而非整篇重读。

## 进阶理解

### 为什么不能直接生成 Todo 开写

模糊需求的错误代码是负资产：返工成本高于前期澄清。澄清段设计：澄清 Agent 对原始需求做缺失信息检测——功能边界（做不做 X）、异常路径、非功能需求（性能/兼容）、隐含约束（存量系统、数据迁移）；输出分批的提问清单（每批 3-5 个问题，避免一次轰炸 20 问让用户敷衍作答），问题按影响面排序。质量度量是『问题覆盖率』：引入的需求缺陷中，澄清段拦截的比例。Spec 与 TD 的区分是本题高频考点：Spec 回答做什么——面向业务的可验收描述；TD 回答怎么做——面向实现的结构决策；跳过 Spec 直接 TD 会把业务歧义固化进技术方案。TD 需按场景分模板：新系统（选型论证为主）、已有系统改造（兼容与回归为主）、重构与数据迁移（分步与回滚为主）。

### 产物的确认、比较与防幻觉

确认机制：阶段间设用户门禁，但降低确认成本——结构化 diff 展示（本版改了哪 3 条，而非整篇重读）、关键决策点高亮征询。产物客观比较是难点：不看下游代码结果时如何评 PRD/TD 好坏——用固定 rubric（完整性、一致性、可测性、风险覆盖、与需求的对齐度）让裁判模型逐维打分，人工复核高风险维度；两个版本对比时逐维 diff 而非给整体分，防止风格差异淹没质量差异。Coding Agent 的幻觉防护专项：引用的 API/库必须存在（代码定位用真实代码库检索而非模型记忆）、生成前先定位相关代码（区别于盲目 grep 之处在于结合代码结构图谱）、测试即规格（验收断言来自 Spec，幻觉代码难过真测试）。Anthropic 的 SWE-bench 实践佐证了这条路线：让 Agent 逐步获得环境 ground truth（执行与测试结果）并迭代修复，是其能解决真实 issue 的关键，同时人的审查仍不可少——自动化验证功能，人类把关方向。

**示例**：用户需求：『给管理后台加个数据导出功能』。

1. 澄清：识别缺失项——导出格式？数据量级与超时处理？权限与脱敏？分批提问两轮。
2. Spec：产出范围（三种格式、10 万行内异步导出、角色权限、手机号脱敏）与验收标准。
3. TD：选型（异步任务+对象存储+下载中心）、接口设计、与现有权限模块的集成方案——用户确认结构化 diff 后拆解为 6 个带验收断言的任务。
4. 实现与回归：逐任务测试全绿；上线前用旧需求回归集确认未破坏既有导出入口。

观察：每个阶段产物都可验收、可比较、可追溯——这是 Coding Agent 从『能写代码』到『能交付功能』的分界线。
