# Q022 · Agent 的评测集怎么构建与分类？评测成本如何计算？没有用户反馈数据时怎么做抽检？

Agent 评测与可靠性 · 中 · `评测集构建` `场景分层` `抽样抽检` `评测成本`

> 真题来源：虾皮 · Agent 开发 · 一面/二面（发帖人自述，未核实）

## 背景描述

评测集是评测体系的地基，追问通常落在集子的来源、分层结构与每次回归的算力成本核算。

## 引出的痛点

随手攒几百条 query 当评测集，分布偏、噪声多、无分层，跑出来的分数既不稳定也不可解释；成本不核算则回归跑不起。

## 考点

评测集来源与清洗、场景分层与规模控制、抽检策略、单次回归的成本口径。

## 思考方向与解题思路

按『来源→清洗分层→规模与成本→抽检策略』四步给可执行方案。

## 推荐答案

评测集构建：以线上真实 query 为主源（脱敏清洗），按场景类型与难度分层采样，辅以边界 case 与对抗样本人工补录；规模控制在能覆盖分布的最小集合并区分全量回归集与冒烟集；成本按『条数 × 平均轮次 × 每轮 token 单价 + 裁判成本』核算；无用户反馈时按风险分层定比抽检并用裁判模型初筛。

- 来源：线上日志脱敏采样为主（分布真实），bad case 回流必进，人工补录边界与对抗 case；避免全用合成数据（分布偏移）。
- 分层：按任务类型（检索型/工具型/多步/拒识类）× 难度（单跳/多跳/干扰项）交叉分层，每层保最低样本量，分数按层报告。
- 规模与成本：全量回归集求覆盖（数百到千级），冒烟集求快（数十条，每次提交跑）；成本 = Σ(条数×平均轮次×token 单价)+裁判/人工抽检费用，按档位算清。
- 稳定性：同集多次运行估计方差（模型有随机性），重大结论看多次均值与显著性，避免单次波动下判断。
- 无反馈抽检：按风险分层定比抽样（高风险场景全检），裁判模型先按维度打分初筛，低分样本人工复核。
- 治理：评测集版本化、进出有记录，防止被训练/提示迭代污染（答案泄漏到提示里）。

## 进阶理解

### 来源与清洗：真实分布优先

从海量线上日志构建有限规模评测集的正确路径：①聚合去重与脱敏——相似 query 聚类后每簇留代表，敏感字段脱敏；②分层采样——按任务类型与难度交叉分层，保证每层有足够样本而不是按原始频率采样（长尾重要场景会被淹没）；③标注——每条配标准答案或可机检的验收断言（规则断言优先于人工标准答案，稳定且免主观）；④补充——边界 case（超长输入、歧义指令、应拒识的请求）与历史 bad case 必入。纯合成数据的风险是分布偏移：生成器想象的用户行为与真实用户差异大，合成集上分数好看、线上不涨——合成可用来扩充，不能做主源。评测集的定位也决定了它是迭代的基准设施——Anthropic 的工程实践同样主张『用全面评测度量性能、在评测之上迭代实现』，评测集正是这一循环的对照组。

### 规模、成本与稳定性

两个集合分工：全量回归集（覆盖优先，数百到千级）在版本变更时跑；冒烟集（数十条核心场景）在每次提交跑。成本口径要算三块：推理成本 = Σ 条数 × 平均 Agent 轮次 × 每轮输入输出 token × 单价（Agent 多轮任务的成本远高于单轮问答，输入 token 随轮次累积）；裁判成本 = 条数 × 裁判模型调用单价（若用 LLM 打分）；人工成本 = 抽检条数 × 单条工时。稳定性容易被忽视：模型与采样温度带来随机性，单次分数波动可能超过两次实验的真实差异——重要对比要多次运行取均值，或用同一随机种子控制变量，避免『跑一遍就下结论』的假阳性。

### 无反馈抽检与防污染

无用户反馈时的抽检策略：按风险分层定比——高风险（涉及资金、不可逆操作、对外输出）全检或高比例，常规场景低比例随机；裁判模型先按预设维度（正确性/完整性/合规性）批量打分初筛，只把低分与边界样本送人工，人力聚焦可疑集。治理两条：①评测集版本化，进出条目留记录，与提示/训练数据物理隔离——标准答案一旦泄漏进提示或微调数据，评测即失效（评测污染）；②定期用线上新分布刷新集子（旧集会逐渐脱离真实流量），并把线上新 bad case 持续回流。

**示例**：客服 Agent 上线三个月，线上日志有 40 万会话，需要建评测集。

1. 聚类去重后按『咨询/办理/投诉/应拒识』× 难度分层采样 800 条，每条配规则断言或短标注。
2. 另补 60 条边界 case 与全部历史 bad case；抽 50 条做冒烟集。
3. 成本核算：全量回归一次约 800×4 轮×token 单价 + 裁判 800 次 + 人工抽检 80 条工时，据此定回归频率。

观察：评测集的质量决定一切迭代判断的可靠性——它的构建本身就是一个小型数据工程项目。
