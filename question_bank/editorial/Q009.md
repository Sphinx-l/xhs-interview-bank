# Q009 · 多轮对话超出模型上下文窗口时如何处理？滑动窗口和动态摘要各适合什么场景？压缩时应该保留哪些信息？

AI Agent 架构设计 · 中 · `上下文压缩` `滑动窗口` `动态摘要` `长对话`

> 真题来源：字节跳动 · Agent Harness · 一面 · 同题另见 6 处（发帖人自述，未核实）

## 背景描述

上下文溢出是长对话与长任务 Agent 的必然事件，面试官考察候选人是否有一套不丢关键信息的压缩策略而非简单截断。

## 引出的痛点

硬截断会丢失早期约束与 tool_call/tool_result 配对，模型行为随即漂移；只知道『做摘要』而不知道保什么、怎么保，会在追问下露馅。

## 考点

各类压缩策略的对比、摘要触发时机、必须保留的信息清单、tool_call 与 tool_result 配对完整性。

## 思考方向与解题思路

先列策略菜单并给适用场景，再给出压缩的内容取舍与工程细节，最后补评分与回灌校验。

## 推荐答案

策略按代价递进：滑动窗口保近期原文、动态摘要压缩早期历史、外置存储把大产物移出窗口按需取回；交互式短会话适合滑动窗口，长任务必须摘要 + 外置组合；压缩时保留任务约束、关键决策与工具调用配对。

- 滑动窗口：只留最近 N 轮原文，零成本无失真但窗外全丢；适合早期内容不重要的短对话。
- 动态摘要：超阈值后把早期历史压成摘要替换原文，保留语义但有损；需迭代更新防摘要漂移。
- 外置存储：检索原文、工具原始返回等大体积产物移出窗口只留句柄，需要时取回。
- 生产常态是混合：约束常驻 + 早期滚动摘要 + 最近 K 轮原文 + 大产物外置。
- 必保清单：任务目标与验收约束、显式指令与偏好、关键决策及理由、关键数据、tool_call 与 tool_result 配对、待办状态。
- 工程细节：阈值设在窗口 60-70%；摘要做结构化输出；压缩后自检关键信息仍可答出。

## 进阶理解

### 策略选型：按信息的时间衰减特性

判断早期信息是否还会被引用：不会→滑动窗口直接裁剪（最便宜）；会但不需要原文→摘要（有损但保留语义）；会且需要精确原文（代码、数据）→外置存储 + 按需取回（无损但多一次检索延迟）。LangChain 记忆文档的表述佐证了必要性：完整历史即使装进窗口，模型也会被陈旧、离题内容『分心』，性能下降且更慢更贵——所以压缩不仅是省空间，更是提升长上下文下的有效性。实践中三种手段叠加：常驻区（System Prompt + 约束 + 长期记忆摘要）+ 滚动摘要区 + 近期原文区，大产物一律外置。

### 压缩什么、保留什么：信息分级

把历史消息按信息类型分级处理：①约束类（用户指令、验收标准、安全边界）——必保，且保持原文措辞进常驻区；②决策类（选择了方案 A、放弃了 B 及原因）——必保，进摘要的决策清单；③事实数据类（工具返回的数字、ID、路径）——小体积保原文，大体积外置留句柄；④过程类（探索失败、寒暄、重复工具调用）——可丢弃或一句话带过；⑤结构约束——tool_call 与对应 tool_result 必须同进同退，配对被切断是压缩最常见的线上事故（模型看到悬空的 tool_call 会报错或重复调用）。摘要输出建议结构化：{任务目标, 已完成, 关键决策, 当前状态, 外置引用列表}，而不是一段自由文本。

### 触发、校验与评分

触发：按 token 阈值（估算器统计当前消息总量）或轮次触发；摘要任务本身用小模型即可降低成本。校验：压缩后跑一次自检问答——用早期关键信息构造问题，验证新上下文仍能答出；不通过则提高保留等级重压。评分：长任务回归集上对比压缩前后任务完成率与关键信息引用率，量化『压缩损失』，而不是只看省了多少 token。多轮重压时注意摘要漂移：每次在旧摘要基础上增量更新，并周期性用原始记录（外置件）校准，避免误差累积。

**示例**：数据分析 Agent 执行 40 轮的长任务，早期用户约束『只看华东数据、输出用万元』，中段拉取了 20 份大报表。

1. 第 15 轮触发压缩：早期对话摘要为结构化块（约束清单含华东/万元，决策清单含口径选择），原文丢弃；20 份报表移到外置存储，窗口只留表名句柄。
2. 第 30 轮再次触发：在旧摘要上增量更新，未完成子任务状态保留。
3. 第 38 轮生成报告：模型从常驻约束区读到『华东、万元』，从外置取回两张需要的报表，报告口径正确。

观察：约束常驻 + 摘要滚动 + 产物外置的组合，让 40 轮长任务在固定窗口内不丢任何决定性信息。
