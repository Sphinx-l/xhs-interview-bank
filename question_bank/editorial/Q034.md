# Q034 · 多模态大模型的具体结构是什么样的？视觉编码器和语言模型如何衔接？

模型选型与微调 · 中 · `多模态架构` `视觉编码器` `模态衔接` `投影层`

> 真题来源：字节跳动 · AI Agent · 三轮技术面+HR面（2-2）（发帖人自述，未核实）

## 背景描述

多模态结构题考的是对『视觉-语言两段式架构』的理解，追问点在衔接层的具体做法与训练策略。

## 引出的痛点

只会说『把图片变成向量拼进 LLM』而说不出视觉 token 怎么来、投影层怎么训、各部分冻不冻结，会被判定没实际了解。

## 考点

视觉编码器（ViT/CLIP 系）、投影衔接层（线性投影 vs Q-Former）、语言模型侧的处理、训练时冻结策略。

## 思考方向与解题思路

按『视觉编码 → 投影衔接 → 语言模型』三段讲结构与职责，再讲两阶段训练与代表性方案的差异。

## 推荐答案

主流多模态大模型是三段式：视觉编码器（ViT/CLIP 系）把图像切成 patch 编为视觉特征序列；投影衔接层把视觉特征对齐到语言模型的向量空间（线性投影或 Q-Former 类查询压缩）；语言模型把视觉 token 与文本 token 拼接后统一处理。训练上先对齐预训练投影层（视觉编码器与 LLM 常冻结或轻调），再做多模态指令微调。

- 视觉编码器：图像切 patch 序列经 ViT 输出特征（或 CLIP 预训练编码器提供对齐性好的特征），多数方案沿用预训练权重。
- 衔接方式一（线性投影，LLaVA 代表）：一个可训练的投影矩阵把每个视觉特征映射为语言模型的输入 embedding，实现简单、保留全部视觉信息。
- 衔接方式二（Q-Former 类）：一组可学习查询向量从视觉特征中抽取固定数量的 token，压缩序列长度但引入信息瓶颈。
- 语言模型侧：视觉 token 与文本 token 拼成统一序列进入 LLM，LLaVA 的定义即『连接视觉编码器与 LLM 的端到端多模态模型』。
- 两阶段训练：先用图文对做对齐预训练（常只训投影层），再用多模态指令数据微调（解冻更多模块）。
- 设计权衡：视觉 token 数量决定分辨率与上下文占用的权衡；投影层容量决定对齐质量与训练成本。

## 进阶理解

### 三段式架构与衔接细节

视觉侧：图像按网格切成 patch（如 14×14 像素一块），每个 patch 经 ViT 编码为一个特征向量，整图变成一个特征序列；使用 CLIP 类预训练编码器的优势是其特征已具图文对齐性，衔接训练更稳。衔接层是本题核心，两种代表做法：①线性投影（LLaVA 路线）——一个（或多层）线性映射把每个视觉特征转为语言模型的输入 embedding，视觉 token 数与 patch 数一致，结构简单信息无损，LLaVA 即以此把视觉编码器与 LLM 端到端连接；②查询压缩（Q-Former 路线）——一组可学习的查询向量通过交叉注意力从视觉特征中提取固定数量（如 32 个）的 token，大幅缩短序列但存在信息瓶颈，适合上下文敏感场景。语言侧：视觉 token 与文本 token 拼接为统一序列输入 LLM，注意力机制天然支持混序处理，LLM 不需要感知『这是图像』——对齐工作已由投影层完成。

### 训练策略与工程权衡

两阶段训练是标配：第一阶段对齐预训练——用大规模图文对（如描述数据），冻结视觉编码器与 LLM、只训投影层，让视觉特征落到 LLM 能理解的语义空间；第二阶段指令微调——用多模态指令数据（图+指令+回答）训练，逐步解冻 LLM 或全部模块，让模型学会按指令看图作答（LLaVA 用 GPT-4 生成的多模态指令数据完成了这一步）。工程权衡三点：①视觉 token 数——越多分辨率越高但占用上下文越多（一张高清图可占数百至数千 token），影响多图与长对话场景；②模块冻结策略——冻结多则训练便宜但对齐上限低，全放开易遗忘语言能力；③编码器选择——CLIP 系通用性好，文档/OCR 场景可能需要更高分辨率编码器或切图策略。

**示例**：报销审核 Agent 需要读发票照片提取金额与税号。

1. 发票图经视觉编码器得到特征序列，线性投影为视觉 token。
2. 用户指令『提取金额与税号，输出 JSON』与视觉 token 拼接进 LLM。
3. 分辨率权衡：发票小字需要高分辨率（更多视觉 token），工程上对票据做裁切分区识别再合并，避免单图吃满上下文。

观察：视觉 token 的数量与质量是 Agent 用好多模态的钥匙——它直接决定『看得清』与『装得下』之间的平衡。
