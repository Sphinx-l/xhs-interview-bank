# Q038 · Agent 的模型幻觉怎么处理？RAG 出现过幻觉吗？幻觉在多 Agent 之间传播怎么防？

Agent 评测与可靠性 · 中 · `幻觉缓解` `RAG忠实度` `跨Agent传播` `溯源`

> 真题来源：面经帖自述信息不详（未核实）

## 背景描述

幻觉是所有 LLM 应用的标配考题，Agent 场景的特殊性在于幻觉会沿链路传播与放大。

## 引出的痛点

只答『提示词里让它别编』是初级答案——材料缺失时的编造、跨 Agent 的伪事实传播，都需要结构性方案。

## 考点

幻觉的成因分类（知识缺失/材料噪声/指令冲突）、对应缓解手段、多 Agent 传播的阻断机制。

## 思考方向与解题思路

先按成因分类给对策，再讲 RAG 场景的忠实度校验，最后讲跨 Agent 阻断。

## 推荐答案

幻觉按成因分三类处理：知识缺失型靠 RAG 补证据并强制引用；材料噪声型靠检索质量与忠实度校验；指令冲突型靠提示结构治理。通用手段是『有据可答、无据则拒』+ 生成后引用回溯校验；多 Agent 场景要给中间结论标置信度与来源，未经证实的信息不得写入共享状态，阻断传播链。

- 成因分类：模型不知道（知识缺失）、材料里有噪声或错误（被带偏）、指令冲突或上下文过载（顾此失彼）。
- 知识缺失型：RAG 补证据 + 提示强制『仅依据材料作答』；检索为空时明确拒答或转人工，不许模型自由发挥。
- 材料噪声型：提升检索精度（重排、过滤过期内容）治源头；生成后做引用回溯——答案里的每个关键论断能否定位到材料。
- 通用校验：忠实度检查（裁判模型对比答案与材料的支持关系）、关键事实抽检、可机检字段用规则验证。
- 跨 Agent 传播阻断：子 Agent 输出带来源与置信度标记，进入共享状态前校验；低置信结论标记为假设而非事实，下游不得当作已验证信息引用。
- 兜底分级：高风险输出（对外、资金相关）幻觉零容忍→全检；低风险场景抽检 + 用户反馈回路。

## 进阶理解

### 对症下药：三类成因三套方案

把『有幻觉』拆成可归因的三类是答题起点。知识缺失型：模型没有相关事实就编——解法是给证据（RAG）并约束使用方式：提示明确『仅依据以下材料回答，材料未覆盖则说明无法回答』，配合检索空结果的显式降级路径。材料噪声型：材料本身错误、过期或检索回了不相关内容，模型忠实转述了错材料——解法在检索侧（重排、时效过滤、来源可信度加权）加生成侧的忠实度校验：答案的关键论断要能回溯到具体材料段，回溯失败即标记可疑。指令冲突型：多约束提示过长互相打架、或历史上下文含早期错误信息——解法是提示结构治理（约束集中在系统层、关键约束常驻）与上下文压缩时保留约束。只写『提示词让它别编』为什么不够：幻觉是概率生成的固有属性，提示只能降低频率，不能保证为零——ReAct 论文的核心动机之一正是：纯思维链推理存在幻觉与错误传播，引入与外部环境（如知识库 API）的交互获取真实反馈才能打断它，所以必须有检索兜底与事后校验两层。

### 多 Agent 传播与阻断

多 Agent 系统的幻觉放大机制：上游 Agent 的编造进入中间结果，下游 Agent 将其作为输入事实继续推理，错误被包装得越来越『可信』——共享状态里的伪事实比单次幻觉危害大得多。阻断设计三条：①来源与置信度随行——每个中间结论携带证据引用与置信标记，写入共享状态前由校验器检查关键论断的可回溯性；②假设与事实分账——低置信、无引用的结论只能以『待验证假设』身份存在，下游引用时必须显式标注，不得升级为事实；③汇聚点复核——主 Agent 汇总各子 Agent 结果时对相互矛盾或无源的条目做二次验证或丢弃。工程上这些机制落在一个统一的中间表示上：结论对象 {内容, 来源列表, 置信度, 状态(已验证/假设)}，比自由文本传递安全得多。

**示例**：多源研报 Agent：A 子 Agent 汇总的数据缺一项，它自行估了一个数。

1. A 的输出：该数据带 no_source 标记与低置信度，以『假设』状态写入共享状态。
2. B（撰写 Agent）引用时按规则显式写『该数据未经来源证实』，而非直接采用。
3. 校验器在汇聚点发现无源数据被多处引用，触发人工复核，A 的估算被替换为检索到的官方口径。

观察：幻觉无法归零，但『标记-阻断-复核』能把单点幻觉从『链路级污染』降级为『可捕获的局部事件』。
