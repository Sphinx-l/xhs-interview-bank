# Q030 · 为控制延迟和成本，Agent 调用大模型有哪些优化策略？缓存、压缩、模型路由各自怎么做？代价与效果如何权衡？

Agent 成本优化 · 中 · `成本优化` `模型路由` `Prompt缓存` `成本效果权衡`

> 真题来源：字节跳动 · AI Agent · 一面（发帖人自述，未核实）

## 背景描述

成本优化是 Agent 商业化的必答题，考察手段清单与『每一分优化都有代价』的权衡意识。

## 引出的痛点

多轮 Agent 的输入 token 随轮次累积重复计费，成本失控常在上线后爆发；只列手段不讲代价与适用边界的回答不合格。

## 考点

缓存（结果缓存与前缀缓存）、上下文压缩、模型路由三手段的原理与代价，以及单位成本效果增量的评估方法。

## 思考方向与解题思路

按三手段展开各给做法与代价，收尾给成本-效果的量化权衡框架。

## 推荐答案

三大手段：缓存（相同子问题结果缓存、系统提示/工具 Schema 前缀缓存）、压缩（滚动摘要与工具结果截断降低累积输入）、模型路由（按任务难度分流到不同档位模型）；每项都有代价（缓存失效、压缩失真、小模型能力边界），权衡靠单位成本的效果增量评估——这是自主系统『用延迟和成本换效果』命题的成本侧。

- 结果缓存：语义相同或完全相同的请求直接返回缓存答案；代价是失效策略（数据变了缓存要跟着失效）与命中率问题。
- 前缀/提示缓存：Agent 每轮输入包含大量重复前缀（系统提示、工具 Schema、历史），利用推理侧前缀缓存（含 KV 复用）大幅降低重复部分成本；需保持前缀字节稳定才易命中。
- 压缩：历史滚动摘要、工具大结果截断/外置，直接降低每轮输入；代价是有损，需保护关键约束与工具调用配对。
- 模型路由：意图分类/难度预估把简单任务分给小模型，复杂任务留给旗舰模型；代价是路由错分的质量风险，需按分错率监控。
- 其他：无依赖工具并行降低时间成本、预算熔断（token/费用上限强制收尾）防失控。
- 权衡框架：对每项手段算『节省成本 vs 质量损失』（回归集上对比），并考虑业务对错误的容忍度——成本优化没有免费的午餐。

## 进阶理解

### 缓存的两层

结果层缓存对『相同问题直接返回』最便宜：命中即零推理成本，工程要点是键设计（精确键 + 语义相似键两档）与失效策略（知识库更新、模型版本变更时批量失效）。前缀层缓存针对 Agent 特有的成本结构：多轮循环中每轮输入都包含系统提示、工具清单与完整历史，这些重复前缀在支持前缀缓存/上下文缓存的推理服务上可按折扣计费甚至本地 KV 复用（与 PagedAttention 的 copy-on-write 前缀共享同源）。命中的工程前提是前缀字节级稳定——把易变内容（时间戳、随机 ID）挪到消息尾部，命中率和成本立见改善。

### 压缩与路由

压缩降低的是累积输入：滚动摘要处理早期历史、工具大结果截断或外置只留摘要与引用，直接把每轮输入从线性增长压平；代价是有损——关键约束、决策、工具调用配对必须保护（见上下文压缩题）。模型路由是结构性省钱：入口做难度预估（规则/小分类器），简单任务（格式转换、单跳问答）路由到小模型，复杂任务留给旗舰模型；按职责选档也是同一思想——规划用强模型、执行用便宜模型。路由的代价是错分：简单判难了浪费钱，难判简单了质量塌方，所以要监控分错率与各档位任务成功率，边界 case 回流调分类器。

### 权衡：算清单位成本的效果增量

Anthropic 对 agentic systems 的定性是经常以延迟和成本换更好的任务表现——成本优化就是在这个交易里重新议价。方法：每项优化在回归集上对比『成本降低 x% / 质量变化 Δ』，并按业务错误容忍度定可接受质量损失上限；优化叠加时要复测（缓存命中改变了输入分布，可能影响路由分类的稳定性）。防失控兜底：任务级 token 与费用预算、熔断收尾、按租户/场景的成本看板——成本可观测是成本可优化的前提。回答时给出『三手段 + 代价 + 量化权衡』的结构，比罗列名词有效得多。

**示例**：客服 Agent 月推理成本 40 万元，需要压降一半且质量不明显下降。

1. 账单分析：70% 成本来自多轮累积输入中的重复前缀与历史。
2. 组合优化：前缀缓存（字节稳定化后命中率 80%，前缀成本约减七成）；历史摘要压缩（输入再降三成）；格式转换类请求路由到小模型（占总请求四成，单价降至 1/10）。
3. 验证：回归集质量分下降 <1%，可接受；月成本降到约 19 万。

观察：先看账单找大头，再按『代价-收益-风险』选组合——成本优化是分析题不是名词默写题。
