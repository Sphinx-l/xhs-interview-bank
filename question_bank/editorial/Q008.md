# Q008 · Agent 的长期记忆应该如何设计？什么条件下写入、如何组织存储、如何召回与更新？用户偏好改变时怎么处理？

AI Agent 架构设计 · 高 · `长期记忆` `记忆写入` `记忆召回` `偏好更新`

> 真题来源：网易互娱 · Agent 开发 · 同题另见 5 处（发帖人自述，未核实）

## 背景描述

长期记忆是 Agent 记忆题的深水区，面试官常沿『写什么→怎么判该写→存哪→怎么取→偏好变了怎么办』连环追问。

## 引出的痛点

全量对话入库会造成记忆污染（噪声、过时、冲突条目泛滥），召回越用越差；没有更新与冲突消解机制，记忆会越积越错。

## 考点

写入准入判断、组织形态（Profile vs Collection）、召回策略、更新与冲突消解、原始对话的追溯保留。

## 思考方向与解题思路

按写入→组织→召回→更新四段展开，每段给出可落地的机制而不是泛泛的分类。

## 推荐答案

长期记忆四要素：写入靠准入判断（规则预筛 + LLM 判定持久价值），存储用结构化 Profile + 向量 Collection 双形态按命名空间组织，召回区分高频直接注入与按需检索，更新按时间戳覆盖并保留原始对话可追溯；偏好改变时新记忆胜出并做冲突消解。

- 写入准入：规则过滤 + LLM 判定类型与置信度；hot path 实时写（透明但增延迟）与 background 异步抽取（不阻塞但有同步时机）两种模式。
- 组织：Profile 单一档案读侧紧凑但更新易丢信息；Collection 窄粒度追加召回率高但要管理增删改；生产常混用。
- 存储：关系库存结构化字段与元数据（时间戳/来源/置信度），向量库支撑语义召回，namespace 隔离。
- 召回：高频关键记忆直接注入系统提示；其余按当前 query 向量召回 TopK 并做时效过滤，控制条数防淹没指令。
- 更新与冲突：同 key 冲突按时间戳取新，旧条目标记失效而非删除；周期性偏好升级为条件记忆。
- 每条记忆存原始对话引用，可回溯审计并支撑遗忘权合规。

## 进阶理解

### 写入：从对话流到记忆条目

写入管线三步：①候选生成——规则先筛掉寒暄、时效性问答，保留自我陈述、显式指令、纠正反馈、情绪反应等信号；②判定——LLM 按 schema 判定是否持久、属于哪类（事实/偏好/程序性经验）、置信度多少；③落库——hot path 模式在回复前由 Agent 主动调用记忆工具（ChatGPT 的 save_memories 即此形态，逐条 upsert），background 模式在会话结束后异步抽取。两者取舍（LangChain 文档有明确对照）：hot path 实时可通知用户但增加推理负担与延迟；background 不阻塞主链路但存在其他线程读到旧记忆的窗口期，需要定周期/事件触发。

### 组织与召回：两种形态的配合

Profile 适合『必须整体在场』的核心画像（用户身份、硬约束），每次带旧 Profile 让模型生成新档案或 JSON patch，规模变大后拆分多文档并做强 schema 校验；Collection 适合长尾事实，新增为主（模型生成新对象比调和旧档案更可靠、下游召回率更高），代价是要解决去重、更新与检索——检索侧用向量相似度 + 内容过滤（时间、类别）。召回时区分两条路径：常驻注入（每轮都放的小集合，几十条以内）与按需检索（与当前 query 相关的 TopK，截断注入）。设计不当的典型症状：记忆条目数膨胀后召回噪声上升，模型被过时条目误导——因此必须有淘汰与置信度衰减。

### 更新、冲突与追溯

偏好改变的处理流程：①检测冲突——新抽取的条目与现有条目同 key/同主题但值不同；②消解——默认时间戳新的胜出，旧条目标记失效而非物理删除（保留审计能力）；对『周期性偏好』（工作日 vs 周末）则升级为条件记忆而非覆盖；③传播——更新 Profile 常驻区，失效 Collection 条目移出召回候选。追溯设计：每条记忆存 source_message_ids，从『Agent 记得我忌口』能回跳到当初的原始对话，既用于调试误写，也满足遗忘权合规（删原始对话时级联处理衍生记忆）。

**示例**：用户上月在助手记忆里是『偏好经济舱』，本月说『以后出行都订商务舱』。

1. 写入：hot path 判定该句为持久偏好变更，生成新记忆条目 {type: preference, key: cabin_class, value: business, ts: 本月, source: msg_812}。
2. 冲突消解：检索到旧条目 {value: economy, ts: 上月}，同 key 冲突，旧条目标记 superseded，新条目生效。
3. 召回：下次订票会话，cabin_class 属于常驻画像直接注入，Agent 默认查商务舱；用户质疑时可回溯 source msg_812 展示依据。

观察：覆盖而非堆叠保证召回侧干净；superseded 状态而非删除保证可审计——这两点是把记忆系统做成可运维系统的关键。
