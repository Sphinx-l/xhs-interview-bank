# Q031 · Prompt 已经调到极限了，下一步怎么办？换模型、升参数还是做 SFT？怎么决策？人工调 Prompt 和自动化调优怎么选？

模型选型与微调 · 高 · `Prompt天花板` `SFT决策` `模型升级` `自动化调优`

> 真题来源：携程 · Agent 开发 · 二面 · 同题另见 2 处（发帖人自述，未核实）

## 背景描述

这是从工程走向算法运营的决策链题：面试官考察候选人能否用数据而非感觉决定『下一步投在哪』。

## 引出的痛点

常见两个极端：无限调 Prompt（修好一类压坏另一类还不承认到顶），或一言不合就 SFT（数据不够、问题不是模型能力导致，浪费一个月）。

## 考点

判断 Prompt 天花板的证据、升级手段的决策树（换模型/升参数/SFT）、人工与自动化 Prompt 优化的选择。

## 思考方向与解题思路

先给『到顶』的判据，再按成本递增排升级选项与适用条件，最后讲调优方式选择。

## 推荐答案

先确认到顶的证据：错误集中在能力缺口而非指令误解、多轮迭代无显著增益、修好一类压坏另一类——满足即该升级。升级按成本递增：换更强/更合适模型 > 同系升参数档 > SFT；SFT 仅当错误模式稳定可标注、数据能规模化收集时才值得。

- 到顶判据：错误归因是能力缺口（推理/知识）而非格式指令问题；迭代多轮指标平台期；跷跷板效应（修 A 坏 B）说明提示已挤满。
- 升级第一档换模型：先在小评测集对比候选模型分数与成本；注意更大不等于更对齐——InstructGPT 论文的核心结论之一即『把模型变大并不能天然更好地遵循用户意图』。
- 升级第二档同系升参数：代价与能力边际要算清，贵档位解决不了知识缺失与数据问题。
- 升级第三档 SFT：错误模式稳定、可构造足量高质量样本（数千级起）、且目标属于示范可学的行为（格式/风格/领域套路）时才投入；AgentTuning 类工作验证了 agent 轨迹微调的可行路径。
- 不适合 SFT 的信号：错误源于检索缺数据、工具报错、知识过时——修数据与工具立竿见影。
- 调优方式：冷启动人工写配小回归集，规模化后上自动化优化（批量生成候选提示→评测打分→择优）。

## 进阶理解

### 判定天花板：让错误说话

把当前 Prompt 的错误样本全量归因：若主要错误是『没看懂复杂约束』『推理链断了』这类能力缺口，提示词空间已经到头——提示只能调动已有能力，不能创造能力；若仍是『格式偶尔崩』『指令被忽略』，还有提示空间。两个量化信号：连续 N 轮迭代在回归集上无显著差异（平台期）；以及典型的跷跷板——为 A 类 case 加的约束伤害了 B 类，说明提示承载的规则已超过模型稳定遵循的带宽。到顶之后继续调是沉没成本，应果断进入升级决策。

### 升级决策树：成本递增、证据驱动

第一档换模型：用同一回归集跑候选模型对比（注意提示要按新模型重写而非直接迁移），决策看分数/成本曲线；关键认知是 InstructGPT 论文的开篇论断——把模型变大并不会天然更好地遵循用户意图，对齐与指令遵循需要专门训练——所以『更大』解决不了所有到顶问题，先测再换。第二档同系升参数：能力边际递减且成本线性上涨，仅在分数差距可度量且业务可承担时选。第三档 SFT：三个前置条件全部满足才启动——错误模式稳定可枚举、能规模收集高质量示范数据（数千级起步）、目标行为属于『示范可学』（格式/风格/领域模式）而非知识注入。SFT 解决不了检索缺数据、工具故障、知识过时——这些是数据与工程问题，修起来比 SFT 快一个数量级。

### 人工与自动化调优

冷启动阶段人工调优最高效：直接对齐业务语义、快速建立小回归集（几十条核心 case）。规模化的标志是改动频繁、case 类型多，此时转入自动化：批量生成候选提示（元提示让模型自己改写）、在回归集上自动打分、择优组合——把『调提示』变成『跑实验』。人工的新职责是维护回归集质量、分析自动化发现不了的反例、以及把控提示的语义边界（自动化可能引入过拟合回归集的规则堆砌）。无论哪种方式，铁律是每次改动都跑回归、版本化管理提示——没有回归集的提示调优等于盲调。

**示例**：工单分类 Agent 的 Prompt 迭代 6 周后准确率停在 82%，错误分析显示长尾类别混淆严重。

1. 归因：长尾类样本训练语料里就少，提示无法补知识——判定能力/知识缺口，到顶。
2. 对比测试：换两档候选模型，强档位到 84% 但成本 3 倍；判断性价比不足。
3. 决策：错误模式稳定且可标注——启动 SFT，用历史正确工单构造 8000 条样本微调小模型，准确率到 89% 且成本更低。

观察：『证据→归因→按成本递增升级』的决策链让每一步投入都可辩护——这正是面试官想听的工程判断力。
