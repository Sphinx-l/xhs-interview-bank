# Q039 · 场景设计：用 Agent 实现一个 AI 面试程序，你会怎么设计？它有什么缺点？需要保证哪些核心指标？怎么避免每步重新规划导致路径震荡？

AI Agent 架构设计 · 高 · `场景设计` `AI面试` `面试官Agent` `路径震荡`

> 真题来源：腾讯 · Agent 开发 · 二面 · 同题另见 3 处（发帖人自述，未核实）

## 背景描述

开放场景设计题，考察把 Workflow/Agent 模式组合成产品的能力——标准追问是产品缺陷、核心指标与路径震荡。

## 引出的痛点

设计成完全自主的单 Agent 会导致面试流程不可控、体验不稳定；不理解路径震荡（每步重新规划推翻前面路径）会暴露工程经验不足。

## 考点

面试流程的编排设计（哪些环节固定、哪些环节自主）、多 Agent 职责划分、缺陷与指标的诚实分析、防震荡机制。

## 思考方向与解题思路

先给整体架构（固定主干+自主追问），再答缺陷与指标，最后专门讲震荡治理。

## 推荐答案

设计原则是『流程固定、内容自主』：面试流程用 Workflow 固化（开场→逐题提问→追问→结束评估），出题与追问两个环节内嵌自主 Agent（根据回答质量动态追问）；指标保面试有效性（题目覆盖、评分一致性）与体验（首响、节奏）；防震荡靠题目与评分计划在阶段开始时锁定，追问只在当前题目局部调整，不允许推翻已完成环节。

- 流程主干（Workflow）：开场建档案→按能力维度出题→每题问答（含 0-2 次追问）→全维度评估报告；主干固定保证体验一致。
- 自主环节一（出题 Agent）：按岗位画像与候选人已答情况动态选题，避免重复考已验证的能力点。
- 自主环节二（追问 Agent）：判断回答深度——答浅了追问细节、答满了一笔带过；追问限定在当前题目的局部上下文。
- 评估环节：评分维度与 rubric 事前锁定，逐题评分 + 全局汇总分离，保证评分一致性（多次面试同一人分数稳定）。
- 诚实缺陷：面试有效性依赖题目质量与评分 rubric；候选人可能用外部工具作弊（需防作弊设计）；纯文本面试损失表达能力维度。
- 防震荡：每个阶段开始时生成并锁定该阶段计划（题目清单/追问预算），执行中只做局部调整；发现整体方向错误的『重规划』限制在阶段边界触发，不做每步全局重规划。

## 进阶理解

### 架构：固定主干 + 两个自主节点

面试天然是『流程已知、内容开放』的场景，适合 Workflow 主干包住自主节点。主干状态机：会话初始化（岗位画像、能力维度权重、题目预算）→ 逐维度提问循环（每维度 1-3 题，每题允许追问链）→ 中场动态调整（薄弱维度加题，已验证维度减题，受总题量预算约束）→ 终局评估（逐题分 + 维度汇总 + 结构化报告）。两个自主节点：出题 Agent 输入岗位画像与已考记录，输出下一题（带考察点标签，保证不重复不遗漏）；追问 Agent 输入当前回答，输出判断（充分/存疑/浅答）与追问问题，追问深度有硬上限防无限纠缠。评估与出题分离是关键设计：评分 rubric 与维度权重在会话开始时固化，评分 Agent 只对单题作答执行 rubric，不参与流程决策——保证评分一致性不被流程动态性污染。

### 缺陷、指标与震荡治理

诚实的产品缺陷分析（面试官问这个是想看批判性）：有效性依赖题库与 rubric 质量——garbage in garbage out；文本面试丢失语音语调与临场表达维度；候选人可用另一 AI 代答，需要节奏异常检测与反作弊题设计；对非常规背景（转行、跨领域）覆盖不足。核心指标两层：体验层——首响延迟、单轮响应时长、会话完成率；有效层——评分一致性（同一答卷多次评分方差、不同场次同人分数相关性）、题目覆盖度（维度与考点覆盖率）、区分度（分数与真实能力的相关性，用后续试用期表现回溯校验）。路径震荡的治理：震荡源于每步都允许全局重规划，后来的观察不断推翻之前的路线。规则化解法：计划分层——会话级计划（维度顺序与预算）只在阶段边界可改，题目级计划在出题时锁定，追问只在题目内部局部自适应；任何推翻已完成环节的意图需要显式理由并记审计。这本质是把 Plan-Execute 的 Re-plan 触发从『每步』收紧到『阶段边界+异常事件』。

**示例**：后端岗位 AI 一面，候选人第二题答得含糊。

1. 追问 Agent 判定『浅答』，在当前题内追问一次具体实现细节（局部调整，不动整体计划）。
2. 再次含糊：记录该考点低分，追问预算用尽，进入下一题——不因单题表现中途重构维度顺序。
3. 中场边界：两个维度均弱，触发阶段级调整，把剩余预算倾斜给关联维度——这是允许全局变更的唯一时机。

观察：面试体验的稳定来自流程刚性，面试质量的上限来自两个自主节点的智能——震荡治理就是不让后者破坏前者。
