# Q018 · 为什么 RAG 检索要用 BM25 关键词 + 向量 Dense 的混合方案？只用向量不行吗？两路结果怎么合并？

RAG 检索与知识组织 · 中 · `混合检索` `BM25` `向量检索` `结果融合`

> 真题来源：字节跳动（抖音） · Agent 开发 · 一面（发帖人自述，未核实）

## 背景描述

混合检索是 RAG 检索层最常被问的选型题，标准追问是『只用 Dense 不行吗』和『两路分数怎么融合』。

## 引出的痛点

把向量检索当成万能方案，遇到术语、编号、生僻词场景召回崩塌；或者两路分数直接相加，量纲不一致导致融合失效。

## 考点

两路检索的互补性（各自失效场景）、融合方法（加权 vs RRF）、以及为什么 RRF 无需调参。

## 思考方向与解题思路

先各打五十大板说清两路的失效面，再讲融合方法对比，给结论与适用条件。

## 推荐答案

BM25 与向量检索互补：向量强在语义泛化（同义改写），弱在精确符号匹配；BM25 强在术语、编号、生僻词的精确命中，弱在措辞差异。只用向量在这些场景会漏召回；两路合并用 RRF（按排名取倒数求和）或加权分数融合，RRF 无需调参且不受两路量纲差异影响，是默认选择。

- 向量检索失效面：产品型号、错误码、人名等低频符号在 Embedding 训练里语义信息少，向量区分度低；专有新词（模型没见过）会被错误泛化。
- BM25 失效面：用户措辞与文档不一致就漏（『退货』vs『售后退回』）；无语义理解，长尾同义词覆盖不了。
- 结论：语义泛化与精确匹配是两种互补能力，生产默认混合，单路只在对成本极敏感或语料极规整时使用。
- 融合方法一：加权分数融合 score = α·norm(dense) + (1-α)·norm(bm25)，需归一化并调 α，语料稳定时可略优于 RRF。
- 融合方法二：RRF 对每路取排名，score = Σ 1/(k + rank)，k 常取 60；只看排名不看分数，天然免疫量纲差异、无需调参，两路或以上检索器等权参与。
- 收益验证：用评测集分别跑单路与混合的召回率/命中率，通常混合对『含术语 query』提升明显；同时监控两路各自的贡献占比防止单路退化无人察觉。

## 进阶理解

### 两路检索的互补性从何而来

Dense 检索把文本压成语义向量，本质是『意思匹配』：它能跨过措辞差异（口语 vs 术语），但压缩也是信息损失——低频符号（型号 A7-2024X、错误码 0x8007、内部缩写）在向量空间里语义信号弱，容易被高频语义淹没；训练分布之外的新词还会被错误地泛化到相近词上。BM25 是词频-逆文档频率的精确匹配：术语、编号、罕见词恰好是它 IDF 权重最高的部分，命中即强信号；但它完全不理解语义，文档说『售后退回』用户问『怎么退货』时可能颗粒无收。两类失效面几乎不重叠，这就是混合的结构性理由——不是锦上添花，而是互相兜底。

### 融合：为什么默认 RRF

两路输出的分数不可直接比较：BM25 是无界的相关性分数，余弦相似度在 [-1,1]，量纲与分布都不同。加权融合要先做归一化（min-max 或按分位数），再调 α，语料与查询分布变化时 α 要重调。RRF（reciprocal rank fusion）绕开分数只用排名：每篇文档的得分 = Σ 1/(k + rank_i)，k 是排名常数（Elasticsearch 默认 60），rank 从 1 开始。它对『多个相关性指标不同的结果集』融合效果好且无需调参——这正是 Elasticsearch 官方文档的定位表述：RRF 将多个具有不同相关性指标的结果集合成一个，无需调优，各指标间也无需相关。两路以上（再加知识图谱路、规则路）同样适用，每路等权。工程上 RRF 是默认，加权融合留给有评测集、语料稳定、愿意持续维护 α 的团队。

### 验证与运维

上线前用标注评测集对比三组：仅 Dense、仅 BM25、混合，看召回率@K 与命中率在 query 分层（术语类/语义类/混合类）上的差异——混合的提升应主要体现在术语类与混合类。上线后监控两路贡献占比（最终入选块来自哪一路），占比长期失衡说明某路退化（如分词词典过期、Embedding 模型未随语料更新），需要告警。另外注意混合召回的 TopK 应给重排留输入（召回 30-50，重排取 3-10），融合只是初筛的收束，不是终点。

**示例**：运维知识库，用户问『服务报 ERR_CONN_RESET_1024 怎么处理』。

1. Dense 路：错误码在向量空间区分度低，召回的是一堆『连接超时排查』类泛化文档。
2. BM25 路：错误码字符串精确命中故障手册对应条目，IDF 权重极高。
3. RRF 融合：故障手册条目在两路都靠前（语义也相关），融合后排第一；纯语义路则把它排到了十名开外。

观察：错误码这类『符号精确』query 是混合检索价值的试金石——单路任何一路都会在这类输入上翻车。
