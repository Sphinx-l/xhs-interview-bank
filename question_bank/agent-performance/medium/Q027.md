# Q027 · 工程侧的推理加速有哪些方向？Continuous Batching 和 KV Cache 是什么？vLLM 这类框架为什么能大幅提升吞吐？

Agent 性能优化 · 中 · `推理加速` `KV Cache` `Continuous Batching` `vLLM`

> 真题来源：携程 · Agent 开发 · 二面（发帖人自述，未核实）

## 背景描述

推理加速是自部署模型团队的高频题，考察对服务层优化（区别于模型压缩）的原理级理解。

## 引出的痛点

只会报框架名字说不清原理——不知道 KV Cache 为什么大、为什么要分页管理、continuous batching 与静态批的差别，一追问就断。

## 考点

推理服务的三类瓶颈、KV Cache 的作用与代价、continuous batching 的机制、PagedAttention 的收益来源。

## 思考方向与解题思路

先给瓶颈全景，再逐个讲 KV Cache、批调度、PagedAttention 的机理与量化收益。

## 推荐答案

推理加速分三层：请求内优化（KV Cache 避免重复计算注意力键值）、批调度优化（continuous batching 动态进出请求消除队头阻塞）、显存管理优化（PagedAttention 分页管理 KV Cache 消除碎片浪费）；vLLM 组合三者，官方口径较 HF Transformers 最高 24 倍吞吐提升。

- KV Cache：自回归生成时缓存已算过的注意力 K/V 张量，避免每步重算全部历史；代价是大（LLaMA-13B 单序列可达 GB 级）且随序列长度动态变化，难管理。
- 传统批处理的问题：静态批要等最慢的序列结束，短请求被迫陪跑；continuous batching 按步粒度动态插入新请求、移除已完成请求，GPU 利用率大幅提升。
- PagedAttention：借鉴操作系统虚拟内存分页，把 KV Cache 切成块按需分配，消除显存碎片与预留浪费——官方分析现有系统因此浪费 60%-80% 显存。
- vLLM 收益来源：分页显存管理允许更大并发，叠加 continuous batching，官方口径较 HF Transformers 最高 24 倍吞吐且不改模型结构。
- Agent 场景的适配点：多轮长上下文任务输入 token 大，注意开启前缀复用/上下文缓存；批量离线任务用高并发档，交互任务保首 token 延迟。
- 选型判断：吞吐瓶颈（排队时间长）优先换推理框架；单请求延迟瓶颈则要靠降输入长度、更小模型或投机解码。

## 进阶理解

### 三类瓶颈与对应优化

自部署 LLM 服务的吞吐瓶颈排序通常是：显存（装不下更多并发）> 调度（批内互相等待）> 计算（GPU 算力本身）。KV Cache 解决的是计算浪费：自回归解码每生成一个 token 都要对全部历史做注意力，缓存历史的 K/V 张量后每步只需算新 token 的部分。但 vLLM 博客指出其两大痛点：大（LLaMA-13B 单序列最高约 1.7GB）与动态（大小随生成长度变化、不可预测）——传统实现按最大长度预留连续显存，其分析指出由此造成的碎片与预留浪费占现有系统显存的 60%-80%，这才是并发上不去的根源。

### Continuous Batching 与 PagedAttention

静态批处理把多个请求打包一起算，但必须等批内最长序列结束才能整批返回，短请求被队头阻塞；continuous batching 把调度粒度降到解码步：每步结束时移除已完成序列、插入排队中的新序列，GPU 始终满载有效工作。PagedAttention 则把每个序列的 KV Cache 切成固定大小的块（block），按逻辑块-物理块映射按需分配，配合 copy-on-write 还能共享相同前缀（系统提示相同的多请求场景）。两者结合，vLLM 的官方口径是较 HuggingFace Transformers 最高 24 倍吞吐提升、不改模型架构。对 Agent 工程的含义：多轮任务的输入里系统提示与工具 Schema 前缀高度重复，前缀块共享与上下文缓存带来的节省非常可观。

**示例**：自部署 13B 模型的 Agent 服务，高峰期请求排队严重，单请求延迟正常。

1. 判断：排队时间长、单请求正常——吞吐瓶颈，优先换 vLLM 类推理框架。
2. 改造后：PagedAttention 让同卡并发数翻数倍，continuous batching 消除批内等待；相同 GPU 吞吐提升数倍。
3. Agent 特有加成：所有请求共享长系统提示，前缀块共享进一步降低显存与首 token 延迟。

观察：推理框架的收益来自显存与调度而不是模型本身——理解『瓶颈在显存管理』是这题的真正考点。
