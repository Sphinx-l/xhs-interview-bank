# Q021 · Agent 系统的效果评测体系怎么设计？除了准确率还要看哪些指标？埋点怎么收集？人工标注还是线上指标？

Agent 评测与可靠性 · 高 · `Agent评测` `指标体系` `任务成功率` `线上指标`

> 真题来源：携程 · AI 应用开发 · 一面 · 同题另见 4 处（发帖人自述，未核实）

## 背景描述

评测体系是 Agent 负责人必答题，考察从离线评测集到线上监控的全链路指标设计，追问常落在『没有用户反馈怎么办』。

## 引出的痛点

只有一个端到端准确率无法定位问题层（模型/检索/工具/编排），也无法支撑迭代决策；没有埋点则线上退化无从发现。

## 考点

分层指标体系（任务层/过程层/资源层）、埋点方案、离线评测与线上监控的关系、无反馈场景的抽检方案。

## 思考方向与解题思路

按三层指标展开，每层给采集方式，再讲离线/在线互补与无反馈兜底。

## 推荐答案

评测体系分三层：任务层看任务成功率与质量分，过程层看工具选错率、参数错误率、检索命中率、循环/超时率，资源层看延迟、成本、token 消耗；埋点在循环每轮记录结构化 Trace；离线评测集管迭代回归，线上指标管实时退化，两者互补，无显式反馈时靠行为信号与人工抽检。

- 任务层指标：任务成功率（可机检验收口径）、输出质量分（规则/裁判模型/人工抽检）、用户信号（采纳率、追问率、点踩、人工接管率）。
- 过程层指标：工具选错率、参数错误率、检索命中率与空检索率、死循环/超预算率、重试率——这层才能定位问题出在哪一环。
- 资源层指标：首字延迟、端到端耗时、单任务 token 与成本、各模型档位消耗。
- 埋点：Agent Loop 每轮落结构化 Trace（轮次、输入摘要、tool_call、结果、耗时、token），配 request 级标签串联会话与版本。
- 离线评测集管回归：覆盖场景分类与难度分层，任何变更（模型/提示/工具）先跑离线；线上指标管退化监控，双阈值告警。
- 无用户反馈时：用隐式行为信号（复制、追问、放弃）+ 定比人工抽检 + 裁判模型批量评分兜底。

## 进阶理解

### 为什么必须分层：准确率无法定位问题

端到端准确率只回答『好不好』，不回答『哪里坏』。一个失败样本可能败在检索没召回、工具参数错、循环超限或模型编造——不分层就无法决定优化投入。过程层指标与 Trace 绑定：每轮记录动作指纹、工具调用与结果、耗时与 token，聚合后得到工具选错率、参数错误率、检索空结果率等；这些过程指标是归因的入口，任务指标是验收的出口。Anthropic 的工程建议同样强调：对 agentic 系统要度量性能并基于度量迭代，把评测当作系统的一等公民而不是事后补丁。

### 埋点与线上监控

埋点设计三原则：①结构化——Trace 按 trace_id/span 组织，每轮 span 记录输入摘要（脱敏）、模型调用、tool_call 与结果、耗时、token、版本号（模型/提示/工具集都要有版本）；②可串联——request 级打上会话 ID、任务类型、灰度分组，支撑后续按维度聚合；③低损耗——采样全量存摘要、失败样本存全量正文。线上监控建两组告警：任务层（成功率环比跌超过阈值）与资源层（成本/延迟突增，常是循环类故障的前兆）。

### 离线/在线互补与无反馈兜底

离线评测集的构建见姊妹题，其职责是回归：每次变更提供可对比的固定基准。线上指标的职责是发现离线覆盖不到的真实分布漂移。两者闭环：线上 bad case 进离线集（防复发），离线集升级反哺监控阈值。没有显式用户反馈时三条兜底：①隐式行为信号——回答被复制/采纳、用户追问纠正、会话中途放弃，都可作弱标签；②定比人工抽检——按风险分层抽样，高风险场景全检；③裁判模型批量评分——用强模型按维度打分初筛，低分样本再人工复核，把人力集中在可疑样本上。回答时强调『指标三层 + 离线在线闭环 + 无反馈三兜底』结构即可覆盖全部追问。

**示例**：报告生成 Agent 上线一个月，需要向团队汇报质量并建立监控。

1. 定义验收断言：报告包含必填章节、数字与来源一致、引用可回溯——可机检部分自动打分。
2. 埋点聚合：过程层发现检索空结果率 8%、参数错误率 3%；资源层发现 P95 耗时受某慢工具拖累。
3. 无反馈兜底：对未获点赞/点踩的会话按 5% 抽检 + 裁判模型全量初筛，低分样本人工复核入回归集。

观察：三层指标让『质量』变成可定位、可监控、可回归的对象，而不是一句『感觉还行』。
